# 代码修改日记

项目：`Proactive Elastic Virtual Network Reconfiguration via Topology Prediction for Dynamic Space-Air-Ground Integrated Networks`

本文记录当前原型从“论文方法骨架”演化到“可运行的启发式闭环、可比较基线和可训练分层 MDP”的实施顺序。日期以当前迭代阶段记录，不将冒烟实验结果视为论文最终结论。

## 阶段 1：建立运行期重配置数据模型

目标：将研究对象从新到达 VNR 的首次嵌入，转为已运行虚拟网络的持续监控与主动重配置。

涉及文件：

- `pe_vnr/topology.py`
- `pe_vnr/dynamic_env.py`

完成内容：

- 新增 `RunningService` 运行期状态：当前部署、剩余生命周期、迁移次数、累计中断时间、SLA 违规次数、业务状态。
- 增加已迁移虚拟节点数和已重路由虚拟链路数，支持后续迁移粒度统计。
- 新增 `TimeVaryingTopology` 历史快照机制，用于表示动态空天地一体化网络。
- 新增 `DynamicTopologyEnv`，使业务可随时间推进、感知当前风险、执行迁移计划并更新部署。

验证：

```bash
python main.py
```

当前限制：仅模拟单个运行中业务；多业务资源竞争和业务到达/离开过程尚未实现。

## 阶段 2：建立启发式风险预测与规则迁移规划闭环

目标：在训练 ST-GCN 和 AC 之前，先得到可解释、可复现的端到端实验基线。

涉及文件：

- `pe_vnr/risk_predictor.py`
- `pe_vnr/planner.py`
- `pe_vnr/config.py`
- `pe_vnr/demo.py`

完成内容：

- 风险预测器在 `use_learned_model=False` 时，根据节点计算余量、排队、能量、链路带宽、时延、丢包和可见时间构造启发式风险。
- 对链路时延和可见时间进行归一化，避免未经归一化的特征使风险饱和到 1。
- 默认禁用未经训练的神经预测器，避免将随机初始化输出误作为预测结果。
- 规则迁移规划器输出 `是否迁移、触发时机、迁移范围、目标虚拟节点、目标虚拟链路`。
- 迁移范围分为 `none`、`link-only`、`partial` 和 `full`。

验证：

```bash
python main.py
```

当前限制：风险预测仍是手工规则，不是论文最终的 ST-GCN 预测模块。

## 阶段 3：建立可比较的规则基线实验

目标：固定同一随机种子和同一拓扑轨迹，形成公平的实验对照组。

涉及文件：

- `run_baselines.py`
- `pe_vnr/metrics.py`

完成内容：

- 新增 `No-Reconfiguration`：维持原部署，不触发干预。
- 新增 `Reactive`：仅在当前端到端时延违反 SLA 后执行重配置。
- 新增 `Heuristic-Proactive`：依据预测风险，在 SLA 违规前执行规则重配置。
- 每个随机种子下三种策略从相同的初始服务和历史拓扑出发。
- 输出 `baseline_runs.csv`，保存逐种子结果。
- 输出 `baseline_summary.csv`，保存均值和标准差。

运行方式：

```bash
python run_baselines.py --seeds 20 --steps 6 --output results
```

当前限制：示例拓扑和业务规模较小，正式实验前需要扩展拓扑规模、业务数量、风险事件类型与随机种子数量。

## 阶段 4：重构执行层为弹性重配置机制

目标：使“部分迁移”“节点迁移”和“链路重路由”具有明确、可量化的执行语义。

涉及文件：

- `pe_vnr/planner.py`
- `pe_vnr/executor.py`
- `pe_vnr/dynamic_env.py`
- `pe_vnr/config.py`

完成内容：

- 对 `partial` 计划，目标虚拟链路被定义为高风险目标虚拟节点的关联链路。
- 执行器只重路由计划指定的虚拟链路；未受影响虚拟链路保留原路径。
- 新增 `ExecutionOutcome`，统一返回候选部署是否接受、迁移原因、迁移前后风险、节点迁移数、链路重路由数及两类成本。
- 新增风险下降约束：默认候选方案必须使服务级风险至少下降 `0.01`；不满足时回退原部署。
- 节点迁移、链路重路由和风险降低均被作为独立执行结果保留。

当前限制：资源账本仍基于单业务简化假设；多业务并发时需引入全局资源账本和事务式资源预留。

## 阶段 5：扩展指标系统

目标：让论文实验能同时评价风险、连续性和迁移代价，而非只比较接受率或资源利用率。

涉及文件：

- `pe_vnr/metrics.py`
- `pe_vnr/dynamic_env.py`

新增逐时隙指标：

- 预测服务风险与重配置后风险。
- 风险下降量。
- 是否成功接受重配置。
- 节点迁移数量与节点迁移成本。
- 链路重路由数量与链路切换成本。
- 总迁移成本、服务中断时间和 SLA 违规。

新增回合汇总指标：

- 平均风险、平均后风险和平均风险下降量。
- 成功接受的重配置次数。
- 总节点迁移数、总链路重路由数。
- 平均节点迁移成本与平均链路切换成本。
- SLA 违规次数。

## 阶段 6：将规划 MDP 和执行 MDP 接入动态环境

目标：让 AC 可以控制真实迁移决策，而不只是对静态向量进行分类。

涉及文件：

- `pe_vnr/mdp/planning_env.py`
- `pe_vnr/mdp/execution_env.py`
- `pe_vnr/dynamic_env.py`
- `pe_vnr/mdp/actor_critic.py`
- `train_hierarchical.py`

完成内容：

- 规划层动作编码为 `是否迁移、延迟时隙、迁移范围`。
- 规划层对冗余的“不迁移”动作施加掩码，避免无意义策略。
- 执行层以逐虚拟节点选择宿主物理节点的方式运行，并为不可行物理节点生成动作掩码。
- `DynamicTopologyEnv` 提供 `reset()`、`planning_step(action)` 和 `execution_step(action)`。
- 新增双 Actor-Critic 的掩码 A2C 参考训练脚本，并分别保存规划策略和执行策略权重。

运行方式：

```bash
python train_hierarchical.py --episodes 100 --output checkpoints
```

当前限制：当前训练器是轻量 A2C 原型，不是最终 PPO + GNN 方案；训练时仍使用启发式风险预测器。

## 阶段 7：已完成验证

已完成以下冒烟验证：

```bash
python main.py
python run_baselines.py --seeds 3 --steps 6 --output results_execution_metrics_smoke
python train_hierarchical.py --episodes 2 --output checkpoints_execution_metrics_smoke
```

在 3 种子功能验证中，`Heuristic-Proactive` 的平均后风险为 `0.5525`，低于 `Reactive` 的 `0.5881` 和 `No-Reconfiguration` 的 `0.5962`。该结果仅说明实现链路正确，不能作为论文正式实验结果。

## 后续顺序

1. 扩展动态场景：多业务、节点/链路故障、可见窗口变化、负载突发和不同拓扑规模。
2. 使用 `20` 至 `30` 个随机种子运行三条规则基线，报告均值、标准差和显著性检验。
3. 在稳定场景和指标基础上训练 AC，并增加随机、贪心、消融策略作为对照。
4. 实现并单独验证 ST-GCN 风险预测器，再用训练后的预测器替换启发式模块。
5. 最后进行“预测器消融、规划层消融、执行层消融、全模型”四类实验。
